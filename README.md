# Лабораторная: свой REST API на Express

## Цель

- Поднять собственный бэкенд на Express и понять, как устроен запрос → ответ.
- Хранить данные **в памяти процесса** — база данных не нужна.
- Описать все запросы в коллекции **Bruno**, проверить их вручную и приложить к работе в папке `bruno`
- Хостить работу не надо: всё проверяется локально.

---

## Варианты сущностей

Придумайте свою сущность, брать отсюда сущности нельзя. У вас должно быть минимум 4 поля помимо `id`

| Сущность         | Поля                              |
| ---------------- | --------------------------------- |
| `Product` товар  | `id`, `title`, `price`, `inStock` |
| `Expense` расход | `id`, `title`, `amount`, `paid`   |

Ниже пошагово разбирается `Product`.

### Поля `Product`

| Поле      | Тип     | Описание                                 |
| --------- | ------- | ---------------------------------------- |
| `id`      | number  | Уникальный идентификатор                 |
| `title`   | string  | Название товара                          |
| `price`   | number  | Цена                                     |
| `inStock` | boolean | Есть ли в наличии (по умолчанию `false`) |

---

## Эндпоинты

| Метод    | URL                 | Что делает                           | Успешный ответ |
| -------- | ------------------- | ------------------------------------ | -------------- |
| `GET`    | `/`                 | Приветствие, проверка что сервер жив | `200`          |
| `GET`    | `/api/products`     | Вернуть все товары                   | `200`          |
| `GET`    | `/api/products/:id` | Вернуть один товар по `id`           | `200` / `404`  |
| `POST`   | `/api/products`     | Создать товар                        | `201`          |
| `PATCH`  | `/api/products/:id` | Частично обновить товар              | `200` / `404`  |
| `DELETE` | `/api/products/:id` | Удалить товар                        | `204` / `404`  |
| `любой`  | неизвестный путь    | Ответ «маршрут не найден»            | `404`          |

## Пошаговая реализация

### Шаг 0. Подготовка проекта

В папке проекта выполните:

```bash
npm init -y
npm i express
mkdir -p routes bruno
```

Так вы создадите файл `package.json`, установите Express и заведёте папки `routes/` и `bruno/`. Остальные файлы появятся на следующих шагах.

В созданном `package.json` измените блок скриптов:

```json
{
    "scripts": {
        "start": "node <имя файла точки входа>",
        "dev": "node --watch <имя файла точки входа>"
    }
}
```

### Шаг 4. Обработчик `GET /` — список товаров

1. В уже созданном обработчике просто верните весь массив в json-ответе через `res.json(...)`.
2. Ничего фильтровать не надо: отдайте `products` целиком.
3. Если массив пуст, клиент получит `[]` — это корректный результат, ошибкой не считается.

---

### Шаг 5. Обработчик `POST /` — создание товара

1. Достаньте из `req.body` поля, которые ждёте от клиента: `title` и `price`. Удобно сделать деструктуризацию: «взять эти свойства из тела запроса».
2. Соберите новый объект:
    - `id` — сгенерируйте, например, через `Date.now()` (получится уникальное число на основе текущего времени);
    - `title` — то, что прислали, обязательно обработайте `.trim()`, чтобы убрать лишние пробелы по краям;
    - `price` — число из тела;
    - `inStock` — `false` по умолчанию, либо значение из тела, если оно пришло.
3. Добавьте объект в конец массива методом `push`.
4. Ответьте статусом **201** (означает «создано») и самим созданным объектом в json.

---

### Шаг 6. Обработчик `GET /:id` — один товар

1. `req.params.id` — это **строка** из адреса. Число `1` и строка `'1'` при строгом сравнении не равны, поэтому либо приведите параметр к числу, либо используйте нестрогое сравнение.
2. Найдите элемент в массиве методом `.find(...)`: сравните `id` товара с параметром из URL. `.find()` вернёт сам объект или `undefined`.
3. Если объект найден — верните его через `res.json(...)`.
4. Если не найден — ответьте `res.status(404).json({ message: '...' })` с текстом про ненайденный id. Перед этим ответом поставьте `return`, чтобы код ниже не выполнился.

---

### Шаг 7. Обработчик `PATCH /:id` — обновление товара

1. Найдите не сам объект, а его **индекс** — методом `.findIndex(...)` с тем же сравнением `id` и `req.params.id`.
2. Если индекс равен `-1`, товара нет: верните `404` с `return`, как на предыдущем шаге.
3. Создайте обновлённый объект, объединив старый товар и то, что прислал клиент: «взять все поля старого объекта, поверх наложить поля из `req.body`». Для этого используется запись `{ ...старый, ...req.body }`. Так не потеряются поля, которые клиент не прислал.
4. Положите обновлённый объект обратно в массив по найденному индексу.
5. Ответьте обновлённым объектом. Важно: отвечайте по **индексу** (`products[productIndex]`), а не по самому объекту — частая ошибка как раз в подстановке объекта вместо индекса, из-за которой ответ ломается.
6. По желанию не давайте клиенту менять `id`: уберите это поле из тела перед объединением.

---

### Шаг 8. Обработчик `DELETE /:id` — удаление товара

1. Сначала найдите товар по `id` так же, как в `GET /:id`. Если его нет — `404` с `return`.
2. Пересоздайте массив методом `.filter(...)`: оставьте только те элементы, чей `id` **не равен** параметру из URL. Присвойте результат той же переменной `products`.
3. Ответьте статусом **204** и завершите ответ через `.end()` — тело в этом случае не отправляется.

## Как сдавать

- Создайте форк репозитория в своей организации с названием `название-этого-репозитория-вашафамилия`.
- Используя ветку `wip`, сделайте задание.
- Зафиксируйте изменения в своём репозитории.
- Когда работа будет готова, создайте пул-реквест из ветки `wip` (своей) в ветку `main` (тоже свою) и укажите `ktkv419` как ревьюера.

Не сливайте изменения в `main` сами — это сделаю я после проверки задания.
